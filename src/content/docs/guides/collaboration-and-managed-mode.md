# Collaboration and managed mode

r0 includes collaboration features and managed-mode controls for supported team workflows. The available collaboration actions and administrator policies can differ by release and organization. Use the controls and policy documentation provided by your build; do not assume that every installation has the same sharing or administration features.

## Before sharing work

1. Confirm which project or workspace you are sharing and who should have access.
2. Remove secrets, personal data, and unrelated files from the workspace before sharing.
3. Check your organization's rules for source code, customer data, and external services.
4. Make sure each participant knows which files or tasks they own to avoid conflicting edits.
5. Use Git branches and reviewable commits to preserve a clear history of code changes.

Collaboration tools do not replace source control or code review. Keep an independent Git backup, review changes before accepting them, and communicate before making overlapping edits.

## Use managed controls

If r0 is managed by an organization, follow the policies shown by your administrator and the documentation for your installed version. A managed setting may be locked intentionally; do not try to bypass it or copy policy-controlled credentials into a personal configuration.

If a feature is unavailable, ask the workspace or organization administrator whether it is supported and enabled. Report unexpected access or policy behavior through your organization's approved support channel.
